# Многопользовательский режим — дизайн

**Дата:** 2026-06-10
**Статус:** утверждён

## Суть

Несколько своих пользователей (семья/друзья) вместо одного. Вход как в Netflix: экран выбора профиля → пароль. Создание профиля прямо на экране входа, защищено общим «кодом семьи» (`APP_PASSWORD` из env). Свободной регистрации нет.

## Модель данных

```
users
  id            TEXT PK (uuid)
  name          TEXT NOT NULL UNIQUE
  password_hash TEXT NOT NULL          -- scrypt из node:crypto, формат "salt:hex"
  created_at    TEXT DEFAULT CURRENT_TIMESTAMP

decks      + user_id TEXT NULL         -- NULL = встроенная (общая), иначе владелец
progress   + user_id TEXT NOT NULL     -- уникальность (user_id, word_id)
study_days → PK (user_id, day)
```

- Встроенные колоды хранятся один раз (`user_id IS NULL`), прогресс по их словам у каждого пользователя свой.
- Пользовательские колоды и слова видны только владельцу. Чужая колода → 404.
- Прогресс, стрик, статистика — личные.
- Миграция старых данных не нужна: прод ещё не разворачивался, локальные тестовые данные (колода «Тест», прогресс, study_days) удаляются миграцией.

## Безопасность

- Пароли: `crypto.scrypt` (N=16384), соль на пользователя, сравнение через `timingSafeEqual`. Без новых зависимостей.
- JWT: `sub = user.id` (сейчас `sub = "owner"`). Старые токены перестают работать — это ок.
- Создание профиля требует `familyCode === APP_PASSWORD`. Неверный код → 403.

## API

```
GET  /api/auth/users      # публичный: [{ id, name }] для экрана выбора
POST /api/auth/register   # { name, password, familyCode } → { token, user }
POST /api/auth/login      # { userId, password } → { token, user }
```

- Auth-middleware достаёт `userId` из JWT (`sub`), кладёт в `req`; несуществующий пользователь → 401.
- Все маршруты колод/слов/тренировок/статистики фильтруют по `userId`:
  - `GET /api/decks` — встроенные + свои
  - запись в чужую/встроенную колоду → 403 (как сейчас для builtin)
  - `training`, `stats`, `study_days` — только свои строки

## Фронтенд

- **Экран входа** заменяется на выбор профиля: сетка карточек-профилей (имя + цветной аватар с первой буквой, hue от имени) + кнопка «Создать профиль».
- Тап по профилю → поле пароля → вход.
- «Создать профиль» → форма: имя, пароль, код семьи → register → автологин.
- Хранение токена не меняется (`wt_token`); дополнительно храним `wt_user` (имя для шапки профиля).
- ProfileScreen показывает имя текущего пользователя; «Выйти» → экран выбора профилей.

## Тесты

- scrypt-хелперы: hash/verify (верный, неверный пароль)
- register: создаёт пользователя, неверный familyCode → 403, дубль имени → 409
- login: верный/неверный пароль, несуществующий userId
- изоляция данных: пользователь A не видит колод и прогресса пользователя B (юнит на уровне репозиториев)
- фронт: экран выбора профилей (список, переход к паролю), форма создания

## Вне scope

- Роли/админка, смена пароля, удаление профиля — не делаем (правится руками в БД).
- Email, восстановление пароля — не нужно.
