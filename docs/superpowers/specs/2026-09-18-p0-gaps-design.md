# Закрытие P0-пробелов: настройки, управление колодами, поиск — дизайн

**Дата:** 2026-09-18
**Статус:** утверждён

## Суть

Пять доработок по итогам аудита функционала. Общая тема — довести до конца то, что уже наполовину есть: подписи, зависящие от языка (сделаны в тренажёре, но не в повторении), настройки профиля (нарисованы, но не работают), копирование слова (есть на сервере, нет в UI), управление колодами (нет ни того, ни другого), поиск в колоде.

Пункты «немецкая озвучка» и «тренировка в рамках колоды» из того же аудита уже реализованы в main и в этот дизайн не входят.

## 1. Язык в подписях повторения

Новый модуль `client/src/lib/languageLabels.ts`. Туда переезжают из `TrainerScreen.tsx`:

```ts
LANG_CODE: Record<string, string>              // en → "EN", de → "DE"
LANG_NAME_ACCUSATIVE: Record<string, string>   // en → "английский", de → "немецкий"
exerciseNames(language): Record<number, string>
directionLabels(language): { key: Direction; label: string; sub: string }[]
typeShort(language): Record<number, string>
```

`ReviewScreen.tsx` берёт `language` из `useAuth()` и строит `DIRS`/`TYPE_SHORT` через эти функции вместо нынешних констант со строками `"EN → RU"`.

Тип `Direction` переименовывается: `"enru" | "ruen" | "both"` → `"toNative" | "toForeign" | "both"`. Старые ключи на немецком означают не то, что написано, — это тот же класс ошибки, что и жёстко зашитые лейблы.

## 2. Настоящие настройки профиля

### Модель данных

Миграция `006_user_settings.sql` — три колонки на `users`, не отдельная таблица: `language` уже живёт там, настроек мало, join не нужен.

```sql
ALTER TABLE users ADD COLUMN daily_goal INTEGER NOT NULL DEFAULT 20
  CHECK (daily_goal > 0);
ALTER TABLE users ADD COLUMN tts_enabled INTEGER NOT NULL DEFAULT 1
  CHECK (tts_enabled IN (0, 1));
ALTER TABLE users ADD COLUMN review_direction TEXT NOT NULL DEFAULT 'both'
  CHECK (review_direction IN ('toNative', 'toForeign', 'both'));
```

`CHECK` в `ADD COLUMN` — тот же приём, что уже применён в `005_add_language.sql`. Дефолты покрывают существующих пользователей, бэкфилл не нужен.

### Сервер

- `users.repository.ts`: `UserRow` и `PublicUser` расширяются полями `daily_goal`, `tts_enabled`, `review_direction`. `updateUserLanguage` заменяется на `updateUserSettings(db, id, patch)`, где `patch` — любое подмножество `{ language, dailyGoal, ttsEnabled, reviewDirection }`.
- `auth.routes.ts`: `PATCH /api/auth/me/language` заменяется на `PATCH /api/auth/me/settings` с тем же набором полей. Валидация: `language ∈ {en, de}`, `dailyGoal` — целое от 1 до 500, `ttsEnabled` — boolean, `reviewDirection ∈ {toNative, toForeign, both}`. Любое невалидное поле → 400, ничего не сохраняется. Старый роут `/language` удаляется — клиент наш, держать два незачем.
- `stats.service.ts`: константа `DAILY_GOAL` удаляется, `getStats(db, userId, now, language, dailyGoal)` получает цель параметром. Пользователя читает роут (`stats.routes.ts`) — так же, как это уже делают `decks.routes` и `training.routes`.

### Клиент

- `auth/token.ts`: `StoredUser` расширяется. **Важно:** в localStorage у уже залогиненных лежит старый объект без новых полей, поэтому при чтении применяются дефолты (`dailyGoal: 20`, `ttsEnabled: true`, `reviewDirection: "both"`), а не предполагается их наличие.
- `auth/authApi.ts`: `setLanguage(language)` → `updateSettings(patch)`.
- `auth/AuthContext.tsx`: `setLanguage` в значении контекста заменяется на `updateSettings(patch)`.
- `ProfileScreen.tsx`: строки становятся кликабельными и переключаются циклом — так же, как уже работает язык, без новых экранов и шитов:
  - **Дневная цель** — 10 → 20 → 30 → 50 → 10
  - **Озвучка слов** — Вкл/Выкл
  - **Направление повторов** — три значения `Direction`, подписи из `languageLabels`
  - строка **«Напоминания»** удаляется: без PWA и Web Push она не заработает, а держать обманку хуже, чем убрать
- `ReviewScreen.tsx`: начальное значение `dir` берётся из `user.reviewDirection` вместо жёсткого `"both"`.

### Выключенная озвучка

`ttsEnabled === false` означает две вещи:

1. Кнопки динамика скрываются в `WordSheet` и в тренажёре (фаза перевода).
2. Упражнение типа 5 («Аудио») исключается из батча: `buildQueue(batch, type, ttsEnabled)` возвращает `[]` для типа 5, а `enterLayer` уже умеет перескакивать пустые слои.

Полоса шагов в `TrainerScreen` строится из отфильтрованного списка — при выключенной озвучке шага 5 в ней нет. Иначе клик по нему уводит в `enterLayer(6)` и досрочно завершает батч.

### Сопутствующий фикс завершения батча

Ручное переключение шагов (`goToLayer`) позволяет прыгнуть сразу на шаг 5, пройти его и через `enterLayer(6)` отправить **весь батч** в `markLearned`, минуя шаги 1–4.

Исправление: `TrainerScreen` ведёт множество пройденных шагов `completed: Set<number>`. Шаг попадает в него, когда набрано `passed >= target`. Батч завершается не по «`enterLayer` дошёл до 6», а по «все доступные шаги (с учётом `ttsEnabled` и наличия примеров) лежат в `completed`». `enterLayer`, не найдя непройденного шага вперёд, идёт по кругу с начала и берёт первый непройденный.

Полоса шагов помечает галочкой те, что в `completed`, — вместо нынешнего `t < layer`, который врёт при прыжке назад.

## 3. Копирование слова в свою колоду

Серверный `POST /api/words/:id/copy` уже есть и покрыт тестами — нужен только клиент.

- `api/wordsApi.ts`: `copyWord(wordId, targetDeckId)`.
- `WordSheet.tsx`: новый необязательный проп `onCopied?: () => void`. Кнопка «В свою колоду» показывается, когда слово открыто из встроенной колоды (`AppShell` передаёт проп при `top.deck.is_builtin === 1`).
- По клику лениво грузится `fetchDecks()`, список фильтруется до личных колод (`is_builtin !== 1`) и разворачивается прямо в шите. Колоды уже приходят отфильтрованными по языку — сервер это делает.
- Если личных колод нет — поле ввода «Новая колода»: `createDeck(name)`, затем `copyWord` в неё.
- После успеха — строка «Скопировано в «X»» в шите и `onCopied()` наверх для инкремента `reloadKey`.

## 4. Управление колодами

### Сервер

- `decks.repository.ts`: `renameDeck(db, id, name)`, `deleteDeckById(db, id)`, `listWordIds(db, deckId)`.
- `decks.routes.ts`:
  - `PATCH /api/decks/:id` — тело `{ name }`. Пустое имя → 400.
  - `DELETE /api/decks/:id` → 204.
  - Оба: колода не найдена или чужая → 404, встроенная → 403 (по образцу `BUILTIN_READONLY` в `words.routes.ts`).
- Каскад работает: `foreign_keys = ON` в `connection.ts`, `words.deck_id` и `progress.word_id` объявлены `ON DELETE CASCADE`. Но mp3 каскадом не удалятся — перед `DELETE` собираются id слов колоды и прогоняются через `deleteAudioFile`, как это делает удаление одного слова. Значит `createDecksRouter` начинает принимать `uploadsDir` (новый параметр deps, по образцу `WordsRouterDeps`).

### Клиент

- `api/decksApi.ts`: `renameDeck(deckId, name)`, `deleteDeck(deckId)`.
- `DeckDetailScreen.tsx`: для личной колоды в шапке — `IconBtn` «edit» и «trash» (справа, там где у встроенной висит плашка «Только чтение»).
  - Переименование: инлайн-режим — вместо заголовка `<input>` с текущим именем, подтверждение галочкой, отмена крестиком. Пустое имя не отправляется.
  - Удаление: `window.confirm` с числом слов и явным предупреждением про прогресс — консистентно с удалением слова в `WordSheet`. После успеха `onBack()` и перезагрузка списка колод.
- Переименованная колода должна отразиться и в заголовке, и в списке колод: `DeckDetailScreen` держит имя в локальном состоянии, наверх уходит `onChanged()` для `reloadKey`.

## 5. Поиск и «показать ещё» в колоде

Целиком в `DeckDetailScreen.tsx`, API не меняется. Колода максимум ~700 слов (~100 КБ JSON), фильтрация в памяти мгновенна и не требует debounce и состояний загрузки.

- Состояние `query` и `visible` (старт 50).
- Фильтр регистронезависимый, `includes` по `foreign_word` и `native_word`.
- Поле поиска рендерится только когда слов больше 20 — на короткой колоде это шум.
- Под списком кнопка «Показать ещё» (+50), видна пока `visible < filtered.length`.
- При смене запроса `visible` сбрасывается на 50 — иначе поиск по одной букве отрисует все 700 карточек.
- Заголовок секции: «Слова (N)», при активном запросе — «Найдено N из M».

## Тесты

Роуты в проекте не покрыты тестами (ни одного `*.routes.test.ts`) — этот расклад не меняем, покрываем репозитории, сервисы, чистую логику и экраны.

**Сервер:**
- `users.repository`: `updateUserSettings` — частичный патч не затирает остальные поля; дефолты у нового пользователя.
- `decks.repository`: `renameDeck`; `deleteDeckById` удаляет колоду, её слова и прогресс по ним (каскад); `listWordIds`.
- `stats.service`: `dailyGoal` приходит параметром и попадает в ответ.
- `db/migrate`: миграция 006 применяется, колонки с дефолтами появляются у существующих пользователей.

**Клиент:**
- `lib/languageLabels`: подписи для `en` и `de`, фолбэк на `en` при неизвестном языке.
- `trainer/trainerLogic`: `buildQueue` с `ttsEnabled: false` даёт пустую очередь для типа 5; тип 3 по-прежнему фильтрует слова без примера.
- `TrainerScreen`: батч не завершается при прыжке на шаг 5 — `markLearned` не вызывается, пока не пройдены остальные шаги; при `ttsEnabled: false` шага 5 нет в полосе.
- `ProfileScreen`: цикл значений по каждой строке вызывает `updateSettings` с ожидаемым патчем; строки «Напоминания» нет.
- `ReviewScreen`: подписи по языку; начальное направление из настроек пользователя.
- `DeckDetailScreen`: поиск фильтрует по обоим полям; «Показать ещё» расширяет окно; сброс окна при смене запроса; поле поиска скрыто на короткой колоде; переименование и удаление доступны только для личной колоды.
- `WordSheet`: кнопка копирования только при переданном пропе; выбор колоды вызывает `copyWord`; пустой список колод даёт поле создания.
- `decksApi` / `wordsApi` / `authApi`: новые методы бьют в нужные URL с нужным телом.

## Вне объёма

Из того же аудита сюда сознательно не входит: PWA и напоминания, таблица истории для графиков, экран сложных слов, градации ответа в SM-2, новые типы упражнений, кнопка «уже знаю это слово», примеры предложений для своих слов, озвучка встроенных слов при сидинге.
